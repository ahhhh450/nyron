## 2. Principal conclusion

The accepted Node Foundation should be retained, not replaced. It already provides durable and immutable Product workflow identity, exact Node-definition version pinning, replay/conflict behavior, layout separation, deterministic projection, Graph publication, and an accepted Module-backed execution path.

Its `ProductNodeDefinition` and `ProductGraphCompiler` are nevertheless a **Module-backed Node specialization**, not a general Node contract:

- `bound_module_ref` and `bound_module_version` are mandatory fields;
- every Product input/output is an alias to a bound Module port;
- registration fails unless the exact Module exists and the Product ports cover its full port surface;
- Product config may only narrow that Module's config schema;
- compilation resolves a Module for every Node and emits exactly one `ModuleInstanceRevision` per NodeInstance.

A bounded Product-layer generalization is safe now if it adds a versioned `NodeExecutionBinding` and proves one genuinely non-Module Product contract through a trusted deterministic BUILTIN lowering adapter, while the final executable Graph remains composed of frozen ordinary Module/Port/Edge facts. This does **not** make Node equal Module: the Product contract, ports, version, config and presentation identity no longer require Module identity; only the chosen Runtime lowering uses an existing frozen executable primitive.

Full SYSTEM_CAPABILITY and multi-agent orchestration are not ready for Production implementation. Several cross-owner Runtime/session semantics require Lead architecture disposition first. Those gaps do not block the narrow pure General Node slice.

## 4. Minimum General NodeDefinition contract

Recommended immutable Product-owned contract:

```text
NodeDefinition
  contract_schema_version
  node_type_ref
  node_version
  input_ports[]
  output_ports[]
  config_schema
  execution_binding
  display_metadata

NodePortDefinition
  port_ref
  value_schema
  ordinal
  input only: activation_mode, connection_policy

NodeExecutionBinding
  kind = MODULE | BUILTIN | SYSTEM_CAPABILITY | COMPOSITE
  binding_ref
  binding_version
  contract_data
```

Rules:

1. `node_type_ref + node_version` is immutable identity. No mutable `latest` lookup is used for an already-published workflow.
2. Node ports are stable Product contracts. They are not Module aliases. A MODULE binding carries an explicit complete Product-port-to-Module-port mapping and is validated against the exact Module version.
3. `config_schema` uses the existing bounded JSON-schema subset. Binding-specific validation may narrow a backend contract but may never grant Capability/Resource/Effect authority.
4. Workflow Core switches only on the closed binding-kind contract, never on `Constant`, `Wait`, `Scheduler Agent`, or another concrete node type. Binding handlers produce a deterministic projection plan.
5. The exact binding ref/version and normalized contract data participate in immutable definition and compiled Graph identity.
6. Lifecycle is separate registry/governance state keyed by exact Node version: `ACTIVE | DEPRECATED | DISABLED | UNAVAILABLE`. It must not delete or rewrite the immutable contract. Historical resolution remains available; new authoring/compilation fails closed according to the state and pinned policy.
7. `DEPRECATED` permits historical and policy-permitted existing use but discourages new authoring; `DISABLED` prevents new execution admission; `UNAVAILABLE` preserves readable identity while required implementation material is absent.

### Backward compatibility

Existing saved `product_node_definitions.contract_json` rows lack `contract_schema_version` and contain mandatory Module fields. They must deserialize as legacy schema v1 and normalize semantically to:


Do not rewrite accepted rows in place. Registration replay must compare normalized semantic contracts while preserving the stored legacy bytes; a semantically conflicting definition under the same exact identity still fails closed. Existing workflows and exact compiled Graph identities must remain byte-for-byte reproducible on the legacy path.

## 9. Dependency subscription / gate re-entry minimum semantics

Required record:

```text
subscription_ref
dependency_owner_ref + dependency_ref
wake_predicate_ref + predicate_version + normalized predicate data
subscriber_ref (gate/task/join)
workflow_execution_ref
subscriber_generation / expected revision
source_cursor_at_registration
state = OPEN | SATISFIED | CLOSED | STALE
delivery_dedupe_ref
created_order / closed_order
```

Correctness requirements:

- registration and the source cursor/watermark use a no-gap protocol so an event between state-read and subscribe is not lost;
- only canonical source events/state transitions relevant to the versioned predicate can satisfy it;
- each source event fans out deterministically to every matching open subscriber, with a distinct stable delivery identity per subscription;
- duplicate notification or restart replay resolves to the same delivery and gate re-entry identity;
- re-entry compares subscriber generation/revision and rejects stale workflow/gate state;
- terminal subscriber/workflow state closes subscriptions and makes later deliveries non-authoritative;
- restart rebuilds matching from durable subscriptions plus source canonical cursor, never in-memory listeners;
- non-relevant transitions do not enqueue a wake; they only advance the safe source cursor where required;
- satisfying and consuming one delivery is atomic with the resulting re-entry authority or uses an equivalent no-gap protocol.

Frozen Runtime already requires durable source Event identity/order/cursor, duplicate-safe EventDelivery, same-Attempt resume and restart replay. Extending this from Attempt-bound Module suspension to arbitrary workflow Task/Gate/Join subscribers changes the subscriber identity and re-entry authority model; that is F-003 and needs Lead disposition before implementation.

## 10. Retry safety

The conservative declaration is directionally correct:

```text
effect_semantics = PURE | CONSEQUENTIAL
idempotency = SAFE | IDEMPOTENCY_KEY_REQUIRED | UNSAFE | UNKNOWN
default = CONSEQUENTIAL + UNKNOWN
```

Invariant accepted without qualification:

```text
UNKNOWN or UNSAFE consequential work != automatic retry clearance
```

However, this declaration cannot itself grant retry permission. Existing frozen authority says Runtime owns retry policy; Module failure/declaration is evidence; Effect/Recovery owns historical outcome and clearance; `FENCED` is not semantic retry clearance. Adding these fields to Node/Module contracts, defining `SAFE`, or interpreting an idempotency key across EffectConflictScope is F-005 and requires exact Lead alignment. The bounded pure slice should omit the generic declaration or fix it to trusted PURE behavior; MODULE preserves its current effect/capability contract unchanged.

## 11. Controlled loop safety

Frozen Graph already states FEEDBACK has no special Runtime semantics and iteration limits/budgets/cancellation are Runtime/Accounting policy facts. Safe minimum:

- `max_iterations` is mandatory and strictly greater than zero;
- each Scheduler iteration commits one validated `CONTINUE | COMPLETE | BLOCKED | ESCALATE` decision as evidence, not direct state truth;
- Runtime increments/compares a canonical loop generation before admitting the next iteration;
- hard `max_generated_tasks` and `max_wall_clock_duration/deadline` are strongly required for agent orchestration;
- any hard-limit hit creates a terminal/failure directive routed to the Failure Handler path; no silent continuation.

The principle is supported by frozen authority. The exact loop-policy schema, counter owner and Scheduler re-entry remain implementation/architecture dependencies; Controlled Loop is not in the first slice.

```text
LOGICAL_CANCEL != EXECUTION_TERMINATED
```

The frozen Runtime already authorizes canonical cancellation requests, fencing of future commit/resume/new-effect authority, stale-result rejection, terminal directives and explicit foreign-owner clearance. A truthful first version must:
