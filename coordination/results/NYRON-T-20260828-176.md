### Minor observation (not a Finding)

The `ALTER TABLE graph_edges ADD COLUMN role TEXT NOT NULL DEFAULT 'NORMAL'` path does not carry the `CHECK (role IN ('NORMAL', 'FEEDBACK'))` constraint that the fresh-create DDL applies to the same column — confirmed by direct read of both code paths. This means a database upgraded via `ALTER TABLE` has one fewer layer of DB-level defense-in-depth than a freshly created one for this specific column. This reviewer independently confirmed the application layer enforces the same constraint regardless: `src/nyron_kernel/graph/revision.py:579` (`if edge.role not in EDGE_ROLES: raise GraphError(...)`, `EDGE_ROLES = frozenset({"NORMAL", "FEEDBACK"})`) validates every `EdgeRequest.role` **before** any row is written, for both fresh and upgraded databases, through the only write path this codebase exposes (`GraphRepository.publish`). This is not raised as a Finding: it is consistent with this Task's own explicit allowance ("or the exact SQLite-safe equivalent preserving current frozen role semantics"), it does not weaken any actual guarantee reachable through the existing Python write path, and adding a matching `CHECK` via `ALTER TABLE` would be optional hardening explicitly out of this Task's scope.
