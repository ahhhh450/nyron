## I. Findings

- **Finding ID**: `NYRON-T-20260828-166-F-001`
  **Type**: `SECURITY`
  **Severity**: `NON_BLOCKING`
  **Location**: `src/nyron_kernel/host/credential/foundation.py:60-87` (`ResolvedCredentialHandle`, `__slots__ = ("__material", "__active")`)
  **Evidence**: On an unconsumed handle, `getattr(handle, "_ResolvedCredentialHandle__material")` returns the raw resolved secret string; `dir(handle)` lists that mangled attribute name; `gc.get_referents(handle)` returns the raw secret value as a direct referent with **no attribute-name knowledge required at all**. All three independently reproduced in this review's probe suite (§H, Probe 2).
  **Impact**: The checklist requirement that "introspection ... paths do not expose secret material" (Task 165 §C / Task 166 item D.19-20) is not fully satisfied under generic Python object introspection — `__slots__` + name mangling obscures the attribute syntactically but does not restrict runtime `getattr`/`gc` access to it. In the code as actually written, this is **not a reachable cross-boundary leak**: no code path in this diff ever hands a `ResolvedCredentialHandle` object reference to anything outside `CredentialResolutionAuthority.use_resolved`'s local scope and the resolver that constructs it; the untrusted consumer callback only ever receives the raw string via the one-time `_use_once` call, which is the intended and required behavior. The exposure would only become reachable if a future code path stored or forwarded a handle *object* (rather than routing exclusively through `_use_once`) to less-trusted code — which this diff does not do anywhere.
  **Required Resolution**: Not required for acceptance of this delivery. If stronger protection is desired in a future iteration: document explicitly (e.g., a class-level invariant comment) that `ResolvedCredentialHandle` object references must never leave the trusted local call scope — only its `_use_once` return value may cross that boundary — since CPython offers no stronger enforcement of this short of out-of-process or `ctypes`-level techniques that would be disproportionate to this bounded foundation's scope.
