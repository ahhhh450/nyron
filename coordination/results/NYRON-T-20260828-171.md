## Graph F-001 / F-002 Closure Evidence

**F-001** (`GraphRepository.publish()` supported only one
`ModuleInstanceRevision` and wrote no `graph_edges` rows): `publish()` now
accepts an ordered sequence of `ModuleInstanceRevision` and an ordered
sequence of `EdgeRequest`, and atomically writes the full multi-instance +
Edge set (`src/nyron_kernel/graph/revision.py`). The pre-existing
single-instance call shape (`publish(ref, single_instance)`) is preserved
unchanged for backward compatibility (`GraphRepository.publish` auto-wraps
a bare `ModuleInstanceRevision`) — all 12 pre-existing test files calling
the old single-instance signature pass unmodified.

**F-002** (edge/port/topology correctness checked too late, only lazily
at Packet-projection time): `publish()` now performs fail-closed
publish-time validation before any row is written:

- missing target/source module instance -> `UNRESOLVED_EDGE_TARGET`;
- missing target/source port -> `UNRESOLVED_EDGE_TARGET_PORT` /
  `UNRESOLVED_EDGE_SOURCE_PORT`;
- wrong port direction (an edge sourced from an input-only port name) is
  caught by the same source-port-resolution check (the port simply is not
  in the module's declared *output* set);
- incompatible schema (exact-match only, per Graph Composite Design
  Candidate §6 OQ-01) -> `EDGE_SCHEMA_INCOMPATIBLE`;
- exact duplicate source-endpoint -> target-endpoint -> `DUPLICATE_EDGE`
  (G-INV-07);
- `SINGLE_SOURCE` / `MULTI_SOURCE` cardinality, **derived from the
  existing frozen input activation-mode set** rather than a new field
  (see "Design Decision: Cardinality" below) -> `EDGE_CARDINALITY_VIOLATION`;
- undeclared cycle / illegal self-loop (G-INV-08), implemented as "remove
  all `FEEDBACK` edges, the remaining `NORMAL`-only subgraph must be
  acyclic" -> `UNDECLARED_GRAPH_CYCLE`; a `FEEDBACK`-marked cycle (including
  a `FEEDBACK` self-loop) remains legal and exercises no special Runtime
  semantics (G-INV-09), unchanged;
- invalid publish leaves **no partial rows and does not advance the
  current-revision pointer**: all structural validation raises before any
  `INSERT` is attempted (validation runs entirely in Python before the
  `with self._store.transaction()` block opens), and any later
  `sqlite3.IntegrityError` inside the transaction (e.g. reusing a
  `module_instance_revision_ref` — globally unique — across two different
  `graph_revision_ref`s) is caught and the whole transaction rolls back.

All of the above are exercised by `tests/kernel/test_graph_multi_instance_edges.py`
(17 tests, including an explicit atomic-rollback-on-conflict test and an
atomic-rollback-on-validation-failure test asserting zero rows written).

### Design Decision: Cardinality (Non-Invented, Derived)

The frozen Graph baseline states the concrete input Port contract
includes "connection policy" (`SINGLE_SOURCE`/`MULTI_SOURCE`), but no
such field exists anywhere in the current, frozen `PortDefinition`
(`src/nyron_kernel/definitions/schema.py`) or in `ModuleInstanceRevision`'s
persisted `input_port_contract` (a bare `{port_name: activation_mode}`
dict). `src/nyron_kernel/definitions/**` is outside this Task's write
surface and is frozen Module authority, so no field was added there.
Instead, `GraphRepository` derives cardinality purely from the existing
frozen activation-mode set: `TRIGGER`/`REQUIRED_NEXT` (consumptive,
exactly-one-source expected) => `SINGLE_SOURCE`; `REQUIRED_LATEST`/
`OPTIONAL_LATEST` (already tolerate multiple deliveries at the existing,
unmodified `ActivationRepository._select_delivery` selection layer) =>
`MULTI_SOURCE`. This adds no new Kernel/Module field or type — it is a
Graph-internal, purely computed publish-time check — and is proven by
`test_single_source_cardinality_overflow_fails_closed` and
`test_multi_source_latest_mode_tolerates_multiple_edges`.

## Findings

### `NYRON-T-20260828-171-F-003`
- **Type:** ARCHITECTURE
- **Severity:** NON_BLOCKING
- **State:** OPEN
- **Location:** `src/nyron_kernel/graph/revision.py` (`GraphRevision.module_instance_revision`
  backward-compatibility property); consumed by
  `src/nyron_kernel/execution/admission.py:94` (`instance = graph.module_instance_revision`).
- **Evidence:** `src/nyron_kernel/execution/admission.py` is outside this
  Task's Bounded Production Write Surfaces and performs one eager,
  single-instance module/config/accounting-scope pre-check before
  admitting a `WorkflowExecution`. It was written when `GraphRevision`
  held exactly one `ModuleInstanceRevision`. For a genuinely
  multi-instance `GraphRevision`, `GraphRevision.module_instance_revision`
  now returns only the *first* instance (stable order: first in the
  `module_instance_revisions` tuple as constructed by the compiler, which
  for the first-slice linear chain is the entrypoint node) rather than
  validating every instance.
- **Impact:** The eager admission-time pre-check is a partial check for
  multi-instance graphs — it does not itself early-reject a second/third
  module with a broken module/config/accounting-scope reference before
  admission succeeds. This does **not** weaken execution correctness: every
  instance's module resolution and input/output contract are still
  independently and fully re-verified per-Activation by the unmodified
  `ActivationRepository._resolve_input_modes` and
  `AttemptExecutor._load_current_evidence` /
  `_prepare_invocation` before any such instance ever actually executes,
  so a broken non-entrypoint instance still fails closed — just later
  (at its own Activation/Attempt, not at admission) than a hypothetical
  fully-generalized multi-instance admission check would. Verified in
  this Task's own E2E test: all three instances (including the two
  non-first ones) execute successfully only because their own
  Activation/Attempt-time checks pass.
- **Required Resolution:** Extending `ExecutionAdmissionGate.admit()` to
  validate every instance in a multi-instance `GraphRevision` eagerly
  (rather than relying on the unmodified per-Activation/Attempt checks)
  requires modifying `src/nyron_kernel/execution/admission.py`, which is
  outside this Task's Bounded Production Write Surfaces
  (`src/nyron_kernel/execution/**` is explicitly listed as not a general
  write surface). Recorded here rather than silently expanding scope, per
  the Task's own Failure/Scope Protocol ("If a change outside the allowed
  surfaces is genuinely required for correctness, STOP and record the
  exact blocker before expanding scope"). Not blocking because it is a
  narrowing of an eager pre-check only, not a correctness gap in the
  final executed result.
