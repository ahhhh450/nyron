## D. Old-SQLite-Schema / Restart Compatibility — Mandatory Adversarial Check Verdict

**Verdict: Reopening a genuinely pre-existing accepted database and publishing any edge-containing GraphRevision (the entire point of this Task's F-001/F-002 closure) crashes with an unhandled `sqlite3.OperationalError`. BLOCKING.**

### Mechanism

`src/nyron_kernel/store/sqlite_store.py` `_create_schema()` declares `graph_edges` (and every other table) with `CREATE TABLE IF NOT EXISTS`, which is a **no-op on a database where the table already exists** — SQLite does not retroactively add columns to satisfy a `CREATE TABLE IF NOT EXISTS` that now includes one. Confirmed the pre-171 `graph_edges` DDL (`git show da426907:src/nyron_kernel/store/sqlite_store.py`) has 8 columns and no `role`; the post-171 DDL adds `role TEXT NOT NULL DEFAULT 'NORMAL' CHECK (...)` as a 9th column, still inside the same `CREATE TABLE IF NOT EXISTS` statement. `GraphRepository.publish()` (`revision.py:290-310`) issues `INSERT INTO graph_edges(..., role) VALUES (..., ?)` explicitly naming the `role` column for every edge, unconditionally.

The codebase already has an established, low-cost idiom for exactly this situation — additive column on an existing table — used elsewhere in this same file for the *unrelated* `runs` table:

```python
# sqlite_store.py:271-282 (pre-existing, unrelated to this Task)
columns = {row["name"] for row in self.connection.execute("PRAGMA table_info(runs)")}
if "terminal_attempt_seq" not in columns:
    self.connection.execute("ALTER TABLE runs ADD COLUMN terminal_attempt_seq INTEGER")
if "terminal_event_ref" not in columns:
    self.connection.execute("ALTER TABLE runs ADD COLUMN terminal_event_ref TEXT")
```

Task 171 did not apply the same idiom to `graph_edges.role`.
