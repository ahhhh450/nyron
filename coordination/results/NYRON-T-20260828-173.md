## B. Destination Canonicalization / Classification — Independently Verified

Verified by direct code reading of `src/nyron_kernel/host/network/foundation.py` plus reviewer-originated reproduction (not merely re-running the executor's 19 tests):

- **Host canonicalization**: `canonicalize_host` rejects leading/trailing whitespace, embedded `/ \ ? # @`, applies IDNA encoding, lower-cases, strips a single trailing dot, then validates every label against `^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$` (standard DNS label grammar — no underscore, no leading/trailing hyphen, no empty label) and rejects all-numeric-label hosts that are not valid IP literals (blocks ambiguous numeric-host parser-bypass attempts). Independently confirmed by direct read, not merely by re-running `test_canonicalization_idna_ipv4_ipv6_and_mapped_ipv6`.
- **Wildcard / label-boundary safety**: `_authorize_destination`'s wildcard match (`pattern.startswith("*.") and requested.host.endswith(pattern[1:]) ...`) matches on `.example.com` (dot-inclusive suffix), which by construction cannot be satisfied by `evil-example.com` (fails `endswith(".example.com")`) — confirmed by direct code reading, not only by the executor's own `test_wildcard_respects_label_boundary`. `canonicalize_host` also independently rejects `*` appearing anywhere in a `RequestedDestination`'s host (the caller-facing side only allows wildcards via the separate `allow_wildcard=True` path used exclusively for `_authorize_destination`'s own scope-pattern parsing) — so a caller cannot smuggle a wildcard into a *requested* destination to widen a match.
- **IPv4-mapped-IPv6 normalization**: `canonicalize_ip` unwraps `IPv6Address.ipv4_mapped` **before** returning the canonical string, so `SelectedPeer.__post_init__` stores the plain IPv4 form for any `::ffff:x.x.x.x` input. Reviewer-originated reproduction (not in the executor's suite) confirms this holds for the **positive/allow** case, not only the deny case the executor's own `test_special_ranges_and_mapped_bypass_fail_closed` exercises:

```text
$ python step4_ipv6_edge_repro.py
mapped-IPv6 global -> 93.184.216.34 classify: GLOBAL
```

## Findings

### `NYRON-T-20260828-173-F-001`
- **Type:** ARCHITECTURE
- **Severity:** NON_BLOCKING
- **Location:** `src/nyron_kernel/host/network/foundation.py:182-198` (`EffectiveDestination`), `:276-277` (`admit()`'s `NETWORK_CONNECTION_ORIGIN_MISMATCH` check).
- **Evidence:** `EffectiveDestination.connection_origin` and `EffectiveDestination.requested` are both fields supplied by the same caller constructing the same immutable object at the same time. `admit()`'s only "connection reuse cannot change logical origin" protection is `effective.connection_origin != effective.requested` — a comparison of two fields on that single caller-supplied object, not a comparison against any durably recorded fact about what a given `connection_ref` was actually first established for. The `reused_connection: bool` field is type-validated but never inspected/branched-on anywhere in `admit()`. The executor's own `test_connection_reuse_cannot_change_logical_origin` exercises exactly this self-consistency check (it sets `connection_origin` to a different `RequestedDestination` than `requested` on the same object and confirms rejection) — it does not, and structurally cannot, exercise an independent "does this connection_ref's *real* prior origin match" check, because no such durable record exists anywhere in this delivery's schema.
- **Impact:** Currently harmless: no real connection exists in this admission-only, no-I/O slice, so there is nothing yet that could truthfully populate `connection_origin` from independently-observed reality even if the broker tried to check it. But this must not be read as "connection-reuse-across-origin is independently enforced" — it enforces only that a caller's own two declared fields are internally consistent. If a future real-transport Task reuses this exact field shape without adding a durable `connection_ref -> first-established-origin` record for the broker to check against, the "reused connection cannot change logical origin" guarantee (Task 168's own required adversarial case, and Task 136's N24) would remain purely cosmetic against a caller that (whether by bug or by compromise) always sets `connection_origin = requested`.
- **Required Resolution:** Not required for acceptance of this admission-only foundation. When a real transport/connection-reuse layer is added, `connection_origin` (or an equivalent) must be derived from a durably recorded, broker-independent fact about the real connection's original destination — not solely from a field the same request-constructing caller also controls — or the check must be explicitly documented as "shape only, enforcement deferred to the real-transport Task" rather than implied to be already-independent.

No other Findings. No BLOCKING findings.
