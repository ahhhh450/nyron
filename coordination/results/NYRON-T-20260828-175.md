## Required Fix — What Changed and Why

`ExecutionAdmissionGate.admit()` (`src/nyron_kernel/execution/admission.py`)
previously resolved `instance = graph.module_instance_revision` — the
backward-compatible accessor documented at
`src/nyron_kernel/graph/revision.py:150-167` as returning only the first
`ModuleInstanceRevision` in stable `module_instance_ref`-sorted order — and
performed module resolution, config resolution, and accounting-scope
resolution against that single instance only.

Frozen `design/Nyron_Runtime_Orchestration_Design_Candidate_v0.1.md` §4.2
"Admission requirements" item 3 is unqualified: "**all** immutable
ModuleInstanceRevision/ModuleDefinition/config references **required by
the revision** resolve" before `WorkflowExecution` admission. For a Graph
beyond the single-instance case, the pre-fix code admitted as long as the
first instance alone resolved, leaving second-and-later instances'
module/config/accounting-scope references unverified at the admission
boundary (Task-172 Finding G, `NYRON-T-20260828-171-F-003`).

The fix replaces the single-instance check with a loop over
`graph.module_instance_revisions` (the full ordered tuple already
populated by the Task-171 multi-instance `GraphRevision`), performing the
same three checks — module resolution against the live `ModuleRegistry`,
config resolution via the injected resolver, and accounting-scope
resolution via `AccountingScopeResolver.resolve()` — for every instance in
order, still fully inside the existing single atomic pre-transaction
validation phase. Any instance's failure raises the same
`AdmissionError` codes as before (`UNRESOLVED_MODULE_REFERENCE`,
`UNRESOLVED_CONFIG_REFERENCE`, or the `AccountingScopeError` code/context
propagated unchanged) and occurs strictly before the
`execution_admissions` / `workflow_executions` transaction, so no partial
or canonical admission fact is ever created for an invalid multi-instance
Graph.

The one-time `_resolve_runtime_policy(runtime_policy_ref)` check (not
per-instance data) was kept as a single check but is now run once before
the per-instance loop rather than interleaved between the first
instance's config and accounting checks; this changes only the relative
firing order between two independent, mutually-exclusive-in-practice
failure classes when both would fail simultaneously (no existing or new
test relies on that interleaving) and does not change any single check's
semantics, pass/fail outcome, or error code.

`graph.module_instance_revision` (the singular backward-compat property)
itself is untouched — it remains available for any other caller — but
`admission.py` no longer uses it.

`graph.executable` (checked first, unchanged) already encodes whether
every instance's module resolved **at publish time**; the per-instance
loop is still required because `ModuleRegistry`/config/accounting state
can change between Graph publish and admission (exactly what the
pre-existing single-instance test
`test_exact_module_version_remains_pinned_without_latest_lookup` already
proves for instance 0 — this Task extends that same live-registry-drift
guarantee to every instance).
