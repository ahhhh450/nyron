## Review Conclusion

The generic Nyron foundation already provides substantial reusable authority, fencing, recovery-evidence and accounting primitives, but the current repository does **not** yet contain the Provider/Model-specific durable external identity, historical-outcome, lookup/cancel, continuation/stream evidence, and ambiguity-to-accounting closure needed to claim crash-safe Provider/Model execution.

A future Provider/Model implementation is safe to open only as a deliberately bounded slice that preserves the existing Owners and treats these missing primitives as mandatory implementation gates. In particular, no implementation may infer retry safety from `FENCED`, a socket close, timeout, missing stream, provider absence, or a local cancellation request.

Because the missing primitives are correctness/security prerequisites for a consequential, billable external Provider/Model effect, the current Provider/Model readiness state is `FAIL` for Production opening. This is not a request to redesign D-008; the frozen semantics are sufficient to define the required boundary.

## Reusable Nyron Surfaces

### 1. Effect Authority — reusable core semantics

`src/nyron_kernel/effect/authority.py` and `src/nyron_kernel/store/sqlite_store.py` already provide:

- durable `PREPARED` before the current bounded external mutation;
- immutable `operation_ref`-bound identity and exact replay conflict detection;
- dispatch admission before `ACTIVE`;
- actual-boundary revalidation of current Attempt authority, CapabilityGrant and ResourceLease;
- durable `ACTIVE`, `REVOKE_REQUESTED`, `FENCED`, `COMPLETED`, `UNKNOWN` states;
- fail-closed transition guards;
- explicit completion and fence evidence;
- `UNKNOWN` rather than guessed history when external evidence is ambiguous.

These are directly reusable semantic foundations. The current implementation is intentionally a filesystem-bounded effect and must not be treated as if its target-file evidence model were already a Provider protocol.

### 2. Attempt replacement / active-conflict fencing

`src/nyron_kernel/execution/replacement.py` proves exact replaced Attempt authority and delegates effect transition to Effect Authority. This is reusable for stopping old work and preventing stale Attempt authority from authorizing new dispatch.

It does **not** determine whether the old semantic external consequence may be repeated. That separation is correct and must remain intact under Amendment 001.

### 3. Recovery Owner

`src/nyron_kernel/recovery/repository.py` already provides:

- one durable reconciliation case per unresolved condition/subject;
- immutable external evidence ingestion;
- bounded/deadlined recovery attempts;
- explicit escalation;
- evidence-backed resolution and disposition;
- retry attempts that are explicitly observation attempts and never execute the external effect.

This is the correct reusable owner for repeated Provider lookup/status/cancel-observation work after ambiguous history. Recovery must not become authority to blindly redispatch the model request.

### 4. Accounting Owner

`src/nyron_kernel/accounting/usage_ledger.py` already provides stable source-dedupe identity for immutable `UsageFact`, optional binding to `operation_ref` / `reservation_ref`, exact duplicate acceptance, conflicting duplicate fail-closed behavior, and append-only adjustments.

`src/nyron_kernel/accounting/settlement_authority.py` provides atomic settlement of a known fact set and replay-safe settlement request identity. These are reusable after Provider usage becomes sufficiently known.

`src/nyron_kernel/accounting/budget_authority.py` provides pre-effect reservation and durable reserved exposure. This is reusable before a billable Provider dispatch.

### 5. Trusted Host / RuntimeContext pattern

`src/nyron_kernel/host/trusted_host.py` and `src/nyron_kernel/host/runtime_context.py` already demonstrate the correct TCB pattern: Modules receive inert handles / bounded brokers instead of Store, DB, raw filesystem/network, or authority objects. The current live broker is only the bounded filesystem write broker; a Provider broker is not yet present.

## Missing Provider / Model Primitives

The minimum future Provider/Model slice needs owner-local equivalents of the following, without changing canonical Owner boundaries:

1. **Stable Provider operation binding** keyed to the Nyron `operation_ref`, including exact Provider adapter/profile revision and request semantic identity.
2. **External idempotency identity persisted before outbound dispatch** when the Provider supports deduplication. The exact transmitted key must be stable across recovery/retry of the same semantic operation and must never be reused for a different semantic operation.
3. **Durable external operation/request ID** captured as set-once evidence when the Provider returns one, with lookup semantics defined by the adapter profile.
4. **Orthogonal active-state and historical-outcome evidence**, equivalent to:
   ```text
   active_state = ACTIVE | FENCED | ...
   historical_outcome = UNKNOWN | PARTIAL | KNOWN
   ```
   The exact storage schema is not frozen here; the semantic distinction is mandatory.
5. **Provider profile semantics** that truthfully declare idempotency scope, duplicate-deduplication guarantees, lookup authority, cancellation confirmation, absence semantics, timeout semantics, and stream-resume capability.
6. **Continuation/resume identity** for Providers that support resuming an existing request/stream. Resume must continue the same external/Nyron operation identity; it is not a new semantic dispatch.
7. **Append-only partial stream evidence** when streaming is enabled, sufficient to distinguish transport-only chunks from durable provider/accounting evidence and to preserve partial usage/history across crash.
8. **Accounting reconciliation hold/closure path** for `UNKNOWN` / `PARTIAL` billable history, so reserved exposure is not incorrectly released or prematurely finalized while Recovery is still resolving actual usage.

## Minimum Safe Future Provider / Model Implementation Boundary

The minimum safe first slice should be intentionally narrower than the full D-008 Provider family:

```text
stateless + unary/non-streaming Provider invocation
+ one exact Provider adapter/profile revision
+ MODEL_INVOKE CapabilityGrant
+ optional ResourceLease only if the Provider handle/session is truly stateful
+ BudgetReservation before billable dispatch
+ EffectOperation PREPARED before any outbound dispatch
+ stable external idempotency key bound before dispatch when supported
+ dispatch-time current Attempt / Grant / Lease revalidation
+ set-once external request ID / acknowledgement evidence
+ authoritative lookup on crash/timeout/disconnect ambiguity
+ cancellation as request; FENCED only after reliable no-future-work evidence
+ historical outcome preserved independently from active fencing
+ Amendment-001 semantic retry gate
+ Recovery observation/lookup/cancel reconciliation for UNKNOWN/PARTIAL history
+ stable UsageFact source identity bound to Provider operation
+ Accounting hold until ambiguous usage becomes sufficiently known
```

The first slice should explicitly exclude:

- token streaming;
- Provider conversation/session continuity unless required by the one selected Provider operation;
- stream continuation/resume;
- request replay to Providers without a documented safe deduplication or authoritative non-dispatch proof;
- any claim that local timeout/disconnect/cancel proves Provider failure or cancellation;
- any rule that treats `FENCED` as semantic retry clearance.

A second bounded slice may enable streaming only after append-only partial evidence, same-operation continuation/resume rules, post-replacement chunk handling, partial usage/accounting behavior and crash tests are present.

## Request Retry vs Continuation / Resume

The future implementation must preserve this distinction:

- **Request retry / redispatch**: another outbound request that may create the same external semantic consequence again. It requires Amendment-001 retry clearance.
- **Continuation / resume**: continued observation or transport of the *same* already-created external request/session/stream, identified by the same Nyron `operation_ref` and Provider external identity. It must not mint a new semantic operation or new idempotency identity merely because the local transport reconnects.
- **Recovery lookup**: an observation to determine old history. Recovery may repeat bounded lookup attempts according to its own retry policy; this does not authorize replay of the Provider effect.

## Streaming Boundary

For one Provider invocation, streaming is normally one EffectOperation, not one EffectOperation per token/chunk. A crash after some chunks creates partial evidence, not proof of failure or permission to restart the request.

Provider token-stream memory must not substitute for Nyron Continuation. Late chunks arriving after Attempt replacement must not be committed as outputs of the replaced Attempt, while authenticated Provider evidence/usage may still need to be retained for effect/accounting reconciliation.
