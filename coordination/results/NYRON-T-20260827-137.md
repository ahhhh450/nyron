## Retry vs Continuation / Resume

- **Retry/redispatch** sends another request capable of creating the same semantic consequence; Amendment-001 retry clearance is required.
- **Continuation/resume** continues the same existing Provider operation, keeping the same Nyron `operation_ref` and durable external identity; transport reconnection must not mint a new semantic operation/idempotency identity.
- **Recovery lookup** observes old history and may itself be retried under Recovery policy; it never authorizes Provider effect replay.

## Streaming Boundary

One Provider invocation is normally one EffectOperation, not one effect per chunk. A stream disconnect after some chunks yields partial/ambiguous evidence, not proof of failure or permission to restart. Provider stream memory is not Nyron Continuation. Late chunks from a replaced Attempt cannot become that Attempt's Runtime output, though authenticated effect/usage evidence may still be retained for reconciliation.
