## Minimum Safe Ingress Sequence

### Prerequisite Slice A — PWP route ownership

Before Track D wires any Production listener/adapter:

1. PWP owns durable `IngressRoute` identity.
2. PWP publishes immutable `IngressRouteRevision`.
3. The exact revision binds at minimum:
   - source adapter/profile identity;
   - authentication policy/profile;
   - freshness/replay policy as applicable;
   - schema/version contract;
   - canonicalization contract;
   - deduplication identity semantics;
   - canonical target Owner / event family;
   - Project/Workspace policy context;
   - exact Graph ingress binding where workflow execution is a target.
4. Adapter resolves one exact route revision before canonical acceptance and never re-resolves mutable `current/latest` semantics after acceptance begins.

### Track D adapter execution

For each received external input:

```text
receive untrusted bytes/message
-> resolve and pin exact PWP IngressRouteRevision
-> establish transport/source context
-> authenticate source when required
-> validate freshness/replay controls
-> validate schema/version/size/required identifiers/source binding
-> canonicalize representation
-> bind stable external source/event identity
-> compute/record canonical payload identity/hash as required
-> apply route-defined deduplication semantics
-> construct target-Owner command + evidence references
-> configured canonical target Owner decides commit
```

Rules:

- authentication success alone never creates canonical truth;
- network reachability is not authentication;
- adapter cannot commit PWP route truth;
- adapter cannot commit arbitrary domain truth;
- same stable identity + conflicting canonical semantics fails closed;
- raw transport payload may be retained only through an explicitly authorized evidence reference policy, not by default canonical embedding.

### Domain-specific target path

For a Human response route:

```text
exact PWP IngressRouteRevision
-> trusted adapter auth/freshness/schema/canonicalization/dedupe
-> evidence-bearing ResponseCandidate command
-> Human Interaction Owner accept_response()
-> immutable HumanResponse / HumanDecisionEvidence
```

This path does not require Runtime `ExecutionIngressFact` if the route stops at Human canonical truth and does not start workflow execution.

If that Human fact later starts a workflow, the transition into Runtime must use a separate Runtime ingress/admission contract; Human business truth does not become generic Runtime ingress truth.

### Generic workflow-start target path

After Finding F-002 is resolved:

```text
exact PWP IngressRouteRevision
-> trusted adapter auth/freshness/schema/canonicalization/dedupe
-> SubmitExecutionIngress(...)
-> Runtime atomically/idempotently commits ExecutionIngressFact
-> exact immutable Graph/context admission
-> Runtime Trigger Packet
-> Delivery
-> Activation
-> Run / Attempt
```

Required replay semantics:

- same stable ingress identity + same canonical payload/context -> observe/return prior committed ingress/admission result;
- same stable ingress identity + conflicting payload/context -> fail closed identity conflict;
- arrival time alone is never identity;
- adapter/PWP never create Activation as a fallback after admission failure.

## Minimum Safe Credential-Boundary Sequence

### A. Configuration / reference layer

1. Durable config carries only approved secret references/binding identities such as PWP `secret_ref` / `secret_refs`, or an adapter profile reference to controlled credential injection.
2. Workflow export/import preserves logical references/requirements only; it does not silently export secret values.
3. A route/provider/profile revision pins which credential binding is intended; mutable environment values do not retroactively rewrite historical execution meaning.

### B. Trusted value-use layer

1. The trusted adapter/broker resolves or receives the credential value inside the TCB.
2. Raw long-lived values are not passed into Module inputs/config, Packet, Continuation, RuntimeContext metadata, or durable canonical facts.
3. For inbound authentication credentials, the value may verify HMAC/token/mTLS/provider identity, but successful verification only produces evidence; it does not authorize target-Owner commit by itself.
4. For outbound/consequential Attempt-owned operations, the adapter revalidates current Attempt/fencing, exact CapabilityGrant scope, and applicable ResourceLease/Effect admission at the actual external-use boundary. Credential possession cannot replace any of them.
5. Advisory capability validation cannot be cached as an authority-use permit.

### C. Evidence / durability / leakage layer

1. Durable records store secret refs/binding IDs, policy refs, authentication evidence refs, external request/event IDs and redacted status — never raw secret values.
2. Adapter exceptions, provider errors, HTTP headers, request dumps and telemetry are redacted before they can cross into durable logs or user-visible errors.
3. Secret-bearing request material is never copied into generic diagnostic metadata.
4. Rotation/rebinding produces a new binding/reference context; historical facts retain their original pinned references and are not silently reinterpreted.

## Explicit Owner-Boundary Constraints

- **PWP Owner** owns `IngressRoute`, immutable `IngressRouteRevision`, Workspace/Project configuration, PolicyContext and EnvironmentBinding configuration. Track D adapters consume exact revisions; they do not mutate or re-own them.
- **External Interface / trusted adapter** owns transport mediation and execution of the configured authentication/freshness/schema/canonicalization/dedup work. It is TCB for the boundary it enforces, but transport receipt is never canonical authority.
- **Runtime Orchestration** owns generic workflow-start `ExecutionIngressFact`, execution admission, Trigger Packet, Delivery, Activation, Run and Attempt truth. Adapter/PWP/domain Owners cannot create Activation directly.
- **Human Interaction Owner** owns `HumanResponse` / Human decision truth. Human ingress evidence is a domain pattern only; Runtime does not re-own Human business truth.
- **Other domain Owners** retain independent business facts (Accounting usage, Effect evidence, Resource/Lease callbacks, etc.) according to their own contracts.
- **Capability Authority** owns CapabilityGrant truth. A credential, provider session, Resource, environment binding or route does not create or widen Capability authority.
- **Resource Manager** owns Resource/ResourceLease live truth. PWP environment binding or credential possession is not live lease evidence.
- **Effect Authority** owns consequential external-operation history and ambiguity/fencing semantics when an ingress-adjacent or credentialed operation is itself an external effect.
- **Owning secret system / controlled adapter credential boundary** owns or supplies raw secret values when such a system/profile exists. D-008 does not assign secret-store internals to Track D. PWP and canonical execution history retain references/binding identities, not values.
