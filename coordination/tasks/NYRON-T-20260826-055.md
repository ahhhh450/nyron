## Exact Replacement Identity

R1 and R2 are Attempts of the **same Run**.

Exact AttemptAuthority tuple:

```text
(execution_ref,
 activation_ref,
 run_ref,
 attempt_seq,
 fencing_token,
 fencing_generation)
```

R1 and R2 share `execution_ref`, `activation_ref`, `run_ref`.
They differ in `attempt_seq`, `fencing_token`, `fencing_generation`.

Never use `run_ref` alone as replacement identity.

## Required Gate-4A Semantics

### A. New Run-owned replacement primitive

Add a narrow `RunRepository.replace_attempt()` or equivalent Run-owned method.

It must execute in one canonical `SQLiteStore.transaction()` / `BEGIN IMMEDIATE` transaction and:

1. fresh-read the current Run row;
2. require caller-supplied expected `current_attempt_seq` and expected `fencing_generation` as a CAS precondition;
3. fail closed with no write on CAS mismatch;
4. require the current R1 attempt state to be replaceable: `CREATED` or `ACTIVE` only;
5. mark exact R1 `(run_ref, attempt_seq=S1)` as terminal `REPLACED`;
6. create exact R2 `(run_ref, attempt_seq=S1+1)` in `CREATED` with a fresh unique fencing token;
7. update `runs.current_attempt_seq = S1+1` and `runs.fencing_generation = G1+1` in the same transaction;
8. return the exact R2 AttemptAuthority / RunAttempt information required by existing callers, without inventing a generalized replacement object model.

The functional authority cutover is the **transaction commit that advances `runs.current_attempt_seq` / fencing generation**.

Revoke propagation is not the cutover and is OUT OF SCOPE in 4A.

### B. Storage invariants

Minimal additive schema changes only.

Required structural invariants:

- `run_attempts.state` supports `REPLACED`;
- legal transitions permit replacement only from live states (`CREATED` / `ACTIVE`), while `REPLACED`, `SUCCEEDED`, `FAILED` remain terminal and cannot reactivate;
- `runs.current_attempt_seq` cannot decrease;
- `runs.fencing_generation` cannot decrease;
- the two advance together by the same positive delta;
- ordinary successful replacement advances each by exactly one;
- raw SQL cannot reactivate R1 or roll the Run back to R1.

Do **not** claim SQLite can prove which Python function issued a write. Triggers prove structural invariants only.

### C. Existing stale-authority cutover must work without rewriting downstream Owners

After replacement commit, using R1's exact stale AttemptAuthority must independently fail at the already-existing boundaries:

- `CapabilityAuthority.issue()` / relevant current-authority validation;
- `ResourceManager.issue_lease()` / relevant current-authority validation;
- `EffectAuthority` dispatch admission for a PREPARED R1 operation.

Expected principle: no production changes in `capability/`, `resource/`, or `effect/` are needed for 4A.

If implementation appears to require modifying those modules merely to make stale R1 fail after `current_attempt_seq` changes:

**STOP and return an Architecture Finding.**

### D. Canonical terminal-commit rejection

Any existing R1 execution/terminal commit path that already requires current Attempt authority must reject R1 after replacement.

Do not add an alternate bypass or special-case commit path.

## Mandatory Tests / Fault Injection

At minimum:

1. Successful R1 -> R2 replacement:
   - same Run / Activation / Execution;
   - R1 becomes `REPLACED`;
   - R2 becomes `CREATED`;
   - seq and fencing generation each increment exactly once;
   - fresh fencing token differs from R1.

2. CAS mismatch on expected attempt sequence:
   - fails closed;
   - no partial R2 row;
   - R1 remains current;
   - generation unchanged.

3. CAS mismatch on expected fencing generation: same guarantees.

4. Replacement source state legality:
   - `CREATED` -> replacement allowed;
   - `ACTIVE` -> replacement allowed;
   - `SUCCEEDED` / `FAILED` / `REPLACED` -> rejected.

5. Atomicity / injected failure:
   - failure after R1 transition but before R2/current pointer completion must roll back the whole transaction;
   - no half-replaced canonical state.

6. Immediately after successful replacement, R1 exact authority:
   - cannot obtain a new CapabilityGrant;
   - cannot obtain a new ResourceLease;
   - cannot admit a new Effect dispatch;
   - cannot canonical-terminal-commit through existing current-Attempt fenced paths.

7. R2 exact authority is current and accepted by the Runtime authority resolver.

8. Raw SQL adversarial checks:
   - cannot reactivate `REPLACED` R1;
   - cannot decrement `current_attempt_seq`;
   - cannot decrement fencing generation;
   - cannot advance only one of the paired counters;
   - cannot drift the counters apart.

9. Complete `tests/kernel` remains green.

10. `git diff --check` and exact authorized-scope verification.
