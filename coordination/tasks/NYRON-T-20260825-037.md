## Required Semantics

### A. Ownership separation

Resource Manager exclusively owns canonical Resource and ResourceLease state.

It MUST NOT:
- issue or mutate CapabilityGrant;
- own Runtime Attempt selection/replacement;
- create EffectOperation;
- own Budget/Recovery truth;
- mutate PWP workspace identity/configuration;
- treat resource existence or lease possession as permission to perform an external effect.

Resource / ResourceLease / CapabilityGrant remain separate facts.

### B. Real bounded Resource: managed local Workspace Handle

Implement one concrete, testable Resource backed by a real filesystem directory beneath a Resource-Manager-owned root supplied explicitly to the manager/adapter.

Minimum canonical Resource fields should preserve the frozen shape as needed:
- `resource_ref`
- `resource_type`
- `resource_owner_ref`
- immutable explicit `scope`
- optional bounded affinity/compatibility descriptor only if actually used
- `state`
- `external_ref` for the managed directory identity/path
- durability/provenance evidence sufficient for crash-safe ownership checks

Use an opaque/versionable `resource_type` identity; do not hardcode product-node taxonomy.

Minimum Resource states for this slice:
- `PROVISIONING`
- `AVAILABLE`
- `DESTROYING`
- `DESTROYED`
- `UNKNOWN`

`LOST` / `ORPHANED` may be implemented only if required by the concrete recovery logic; do not add unused lifecycle machinery.

Rules:
- canonical `PROVISIONING` identity MUST commit before external directory creation;
- the external directory path/identity must be deterministically and safely bound to the exact `resource_ref` under the manager-owned root;
- path traversal / caller-controlled escape from the manager root must fail closed;
- an existing unproven/mismatched directory must never be silently adopted;
- Resource state is not `LEASED`; leasing is separate;
- same `resource_ref` cannot be rebound to another resource type/owner/scope/external identity;
- exact replay may be idempotent only where identity/evidence is identical.

### C. Provision / crash recovery

Provide executable crash-window behavior for the concrete directory Resource.

At minimum prove:

1. crash/stop after durable `PROVISIONING` but before directory creation leaves recoverable canonical intent;
2. restart can safely retry creation when authoritative evidence proves the exact managed path has not been created;
3. crash/stop after directory creation but before `AVAILABLE` commit can recover to `AVAILABLE` only when manager-owned provenance/marker evidence proves the directory belongs to that exact `resource_ref`;
4. ambiguous/mismatched external state fails closed to `UNKNOWN` (or explicit ORPHANED if justified), never guessed AVAILABLE;
5. reopening SQLite + Resource Manager preserves canonical Resource facts exactly.

Use the narrowest provenance mechanism needed (for example, a manager-owned marker file or equivalent exact identity evidence). Do not build a generalized external-resource adoption framework.

### D. ResourceLease canonical lifecycle

Implement ResourceLease as a separate canonical fact.

Minimum binding:
- `lease_ref`
- `resource_ref`
- `lease_holder_ref`
- exact Runtime `execution_ref`
- `activation_ref`
- `run_ref`
- `attempt_seq`
- `fencing_token`
- `fencing_generation`
- `issued_at`
- `expires_at?`
- `state`

Minimum states for this slice:
- `ACTIVE`
- `REVOKE_REQUESTED`
- `RELEASED`
- `EXPIRED`
- `UNKNOWN`

Use `EXPIRING` only if current behavior truly requires a distinct durable intermediate state; otherwise defer it.

Rules:
- lease can be issued only for an `AVAILABLE` Resource and exact current Runtime Attempt authority;
- stale/mismatched Attempt/fencing cannot obtain a new Lease;
- Lease is non-transferable and immutable in binding/scope identity;
- same lease_ref cannot be rebound;
- exact replay may be idempotent if fully identical;
- release is durable and future validation rejects the Lease;
- revoke terminates future lease authority; it does not fabricate external Resource destruction;
- expiry terminates future lease authority; Resource may remain AVAILABLE;
- stale Runtime authority causes lease validation to fail closed even before asynchronous revoke propagation;
- persisted leases survive reopen exactly.

### E. Lease validation is advisory/non-consumptive

A `ValidateLease`-equivalent query may exist but is advisory only in this gate.

It MUST re-check:
- exact Lease identity/state/time validity;
- exact Resource identity/state;
- exact current Runtime Attempt/fencing authority.

It MUST NOT become a cached permission to later perform an external effect or foreign canonical mutation.

Clarification 004 remains binding:

`plain check-then-use is forbidden`.

Do not create a hypothetical multi-authority admission permit merely to prepare for EffectOperation. Race-safe authority consumption remains for the real Effect/Command boundary.

### F. Destroy / release boundary

Provide the narrowest safe Resource destruction lifecycle:

- commit `DESTROYING` before external directory removal;
- remove only the exact manager-owned directory proven to belong to this `resource_ref`;
- commit `DESTROYED` only after authoritative evidence confirms removal/nonexistence;
- ambiguous state becomes `UNKNOWN` rather than guessed destroyed;
- active Leases must prevent destruction unless the Task's explicit lifecycle has first moved them out of ACTIVE authority;
- do not implement global cascading policy or Runtime retry/replacement.

Tests must use Task-owned temporary directories only. Never touch user/workspace repository directories outside the test sandbox.
