## Required EffectOperation Handling

Discover only exact-R1 rows in:

```text
PREPARED
ACTIVE
REVOKE_REQUESTED
```

`FENCED`, `COMPLETED`, `UNKNOWN` are terminal and must remain untouched.

For every selected row, use only existing `EffectAuthority` APIs.

### PREPARED

Call existing `request_revoke(operation_ref)`.

Expected accepted Gate-3 truth:

- exact target `ABSENT` -> existing Owner may truthfully `FENCED` as `PREPARED_NEVER_ACTIVE`;
- target mismatch/ambiguity -> `UNKNOWN`;
- replacement itself is never fence evidence.

### ACTIVE

Call existing `request_revoke(operation_ref)` first:

```text
ACTIVE -> REVOKE_REQUESTED
```

Then Gate-4B may synchronously call existing `resolve_revoke(operation_ref)`.

Required truth:

- exact completion evidence -> `COMPLETED`;
- absent/mismatch/ambiguous evidence where this coordinator cannot prove executor cessation -> `UNKNOWN`;
- **do not fabricate `FENCED` merely because replacement occurred or target is absent**.

If the original executor later resumes and fresh-reads `REVOKE_REQUESTED` before its first mutation, the already-accepted Gate-3 executor path may independently produce truthful `EXECUTOR_STOPPED_BEFORE_FIRST_MUTATION` fence evidence. Gate-4B coordinator must not impersonate that proof.

### REVOKE_REQUESTED

Use existing `resolve_revoke()` only.

- exact completion evidence -> `COMPLETED`;
- otherwise current Gate-3 semantics fail closed to `UNKNOWN` unless exact cessation is independently established by the rightful executor path;
- idempotent repeated orchestration must not manufacture new evidence.
