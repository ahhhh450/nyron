## Required Production Scope

### A. Bounded Graph Subsystem Completion

Close Task-170 F-001/F-002 against already-frozen Graph semantics.

Required:

1. Extend the Graph Python object/write path so one `GraphRevision` can atomically contain an ordered set of `ModuleInstanceRevision`s and an ordered set of `Edge`s.
2. Extend `GraphRepository.publish()` (or the narrowest existing Graph-owned publication surface) from the current single-instance stub to publish the complete multi-instance + Edge set in one transaction.
3. Preserve immutable/idempotent publication semantics:
   - identical replay returns/accepts the identical revision deterministically;
   - conflicting content under the same immutable revision identity fails closed;
   - invalid publication MUST NOT leave partial module-instance/edge rows or advance any current revision pointer.
4. Perform frozen Graph validation before successful publication, including at minimum:
   - all referenced module instances exist;
   - all source/target ports exist and direction is valid;
   - exact schema compatibility under the existing frozen rule;
   - `SINGLE_SOURCE` / `MULTI_SOURCE` cardinality;
   - duplicate illegal Edge rejection;
   - frozen cycle/`FEEDBACK` rule;
   - deterministic Edge ordering / existing ordinal invariants;
   - unresolved ModuleDefinition/config references fail closed through existing Graph/Module authority.
5. Do not invent a new Graph semantic, type system, branch primitive, scheduler, or execution mechanism.

Prefer existing Graph tables. Task 170 verified that the current SQLite schema already has multi-instance and `graph_edges` support; do not add replacement Graph truth tables unless actual code proves a strictly required bounded schema correction.

### B. New Product Subsystem — Minimum Foundation

Add the smallest Product-owned subsystem needed to represent, persist, restore, validate, and compile a visual/module-assembly workflow.

Minimum required models/contracts:

1. `ProductNodeDefinition`
   - Product-owned stable node-type identity + exact Product node version;
   - exact `bound_module_ref@version` only — never `latest/current/range`;
   - Product-facing port bindings that reference existing Module ports without copying/re-owning Module authority;
   - Product config schema may narrow/present Module config but MUST NOT widen Module authority or capability.

2. Product-facing port definition
   - stable Product port identity;
   - exact binding to one Module input/output port;
   - schema identical/compatible only under existing frozen authority;
   - stable ordinal where required;
   - input activation/cardinality policy may only mirror existing Module/Graph semantics;
   - no streaming semantics in this Task.

3. `NodeInstance`
   - workflow-local stable instance identity;
   - exact `ProductNodeDefinition@version` pin;
   - immutable/addressable config snapshot/ref;
   - optional Product-only label/presentation reference;
   - no Runtime execution authority.

4. `NodeConnection`
   - source node/output Product port → target node/input Product port;
   - fail closed on unresolved node/port, wrong direction, schema mismatch, illegal duplicate, cardinality overflow;
   - pass through existing `NORMAL | FEEDBACK` role only if required by frozen Graph semantics; do not invent new cycle semantics.

5. `VisualWorkflowRevision`
   - immutable `workflow_ref` + `workflow_revision_ref` identity;
   - predecessor lineage;
   - immutable node set, connection set, exact dependency/version bindings, entrypoint(s), Product output(s), Product metadata;
   - identical replay deterministic/idempotent;
   - conflicting same revision identity fails closed;
   - existing revision is never silently mutated;
   - restart restores the exact revision and exact pinned dependencies.

6. `WorkflowLayoutRecord` or equivalently narrow separate Product presentation record
   - canvas/layout-only state lives outside immutable executable workflow truth;
   - moving a node on the canvas MUST NOT require or silently cause a new `GraphRevision`.

### C. Deterministic Product → Graph Compiler

Implement a Product-owned, stateless/deterministic compile/projection seam:

```text
VisualWorkflowRevision
        ↓ Product validation + exact node/module resolution
Product compiler
        ↓ GraphRepository.publish(...)
GraphRevision
```

Required properties:

- resolves exact `ProductNodeDefinition@version` and exact `ModuleDefinition@version`;
- maps `NodeInstance` to existing Graph `module_instance_ref` / `ModuleInstanceRevision` semantics;
- maps `NodeConnection` to existing Graph Edge semantics;
- Product does not write Graph tables directly except by calling the Graph-owned publication API;
- same immutable workflow revision + same exact dependencies deterministically produces the same Graph revision identity/content;
- recompilation after process restart remains deterministic;
- traceability to exact Product workflow revision may be stored only as non-authoritative provenance if needed; it must not become execution authority;
- compile failure MUST NOT produce a partially valid executable Graph revision.

If implementation proves that a required cross-owner semantic is not already frozen, STOP and return a blocker / Architecture Finding. Do not invent the missing authority inside this Task.
