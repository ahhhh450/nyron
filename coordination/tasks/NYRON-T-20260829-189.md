```text
NodeDefinition != ModuleDefinition
```

## Required Production Scope

### A. Generalize Product Node Definition

Refactor the current Module-specific `ProductNodeDefinition` into a binding-neutral immutable definition contract.

Required common facts:

- stable `node_type_ref` identity;
- exact immutable `node_version`;
- `contract_schema_version` for serialized contract evolution;
- Product-owned input/output port definitions independent of Module port aliases;
- Product config schema;
- tagged `NodeExecutionBinding`;
- Product display metadata;
- immutable exact-version conflict/replay behavior.

A Product port definition should include only the minimum facts needed by current Product validation/compile, expected approximately:

```text
port_ref
value_schema
ordinal
input only: activation_mode / connection_policy where already needed
```

Do not widen Graph/Module schema semantics. Use only existing accepted schema/activation/cardinality concepts.

### B. Preserve Existing MODULE Binding Exactly

Move current Module-specific fields/validation into the `MODULE` execution-binding contract/handler.

MODULE must preserve:

- exact `module_ref@version` binding;
- complete Product-port ↔ Module-port mapping;
- Module existence/version validation;
- Product config narrowing / no authority widening;
- existing Graph projection to `ModuleInstanceRevision`;
- current accounting/admission/runtime behavior;
- deterministic persisted/restarted behavior.

Do not change Module Registry semantics.

### C. Legacy Serialization / Backward Compatibility

Existing accepted `product_node_definitions.contract_json` rows are canonical accepted persisted data.

They lack `contract_schema_version` and contain mandatory Module-specific fields.

Required behavior:

1. Treat current accepted rows as legacy Product definition schema v1.
2. Deserialize/normalize them semantically into the new general representation with:

```text
execution_binding.kind = MODULE
```

and the same exact module/version/port mapping/config semantics.
3. Do NOT rewrite existing canonical rows in place merely to upgrade shape.
4. Identical legacy registration/replay remains idempotent.
5. A semantically conflicting definition under the same exact node identity fails closed.
6. Existing saved workflows continue to resolve their exact old node versions after restart.
7. Existing accepted Module-backed workflow compilation must preserve its previous exact Graph identity/content. If the new normalized representation would change deterministic identity for legacy workflows, maintain an explicit legacy identity path rather than silently changing accepted Graph identity.

No generic migration framework is authorized.

### D. Introduce BUILTIN / PURE Binding

Implement one trusted versioned Product-owned BUILTIN lowering mechanism under `src/nyron_kernel/product/**`.

Requirements:

- Node definition itself contains no `module_ref`, `module_version`, or Module-port aliases.
- `NodeExecutionBinding(kind=BUILTIN, binding_ref, binding_version, ...)` selects an exact trusted lowering handler.
- Unknown `binding_ref@version` fails closed.
- Handler is deterministic and side-effect-free.
- Handler may lower one Product Node into one or more existing registered PURE internal Module leaves + ordinary Graph Edges.
- Lowering output must be validated before Graph publication.
- Product/handler must call Graph-owned publication APIs; it must not write Graph tables directly.
- Handler must never create CapabilityGrant/Effect/Resource authority.
- No real external effect.

This is an implementation seam, not a new Kernel execution path.

### E. First Genuine Non-Module Node — Constant

Implement exactly one Product `Constant` Node as the proof of Node independence.

The Product-level Constant contract must:

- have a Product-owned exact node identity/version;
- have no mandatory Module identity anywhere in the Node contract;
- use Product-owned output port definition;
- store its constant value in bounded immutable Product config;
- bind to an exact BUILTIN lowering handler;
- persist/restart/replay deterministically;
- compile through trusted lowering into existing PURE Graph/Runtime leaves;
- execute through the normal existing Runtime path.

It is acceptable for the trusted lowering implementation to reuse the already accepted internal PURE constant Module as a leaf, provided the Product node contract itself is not Module-shaped and the lowering is fully hidden behind the BUILTIN binding handler.

Do not implement Transform/Condition/Switch/Map or other nodes in this Task.

### F. Binding-Neutral Workflow Validation

Adjust Product workflow/port validation only as required so `NodeConnection`, entrypoints and outputs validate against Product-owned Node ports rather than assuming every Product port is a Module alias.

Preserve:

- unresolved node/port fail closed;
- direction/schema/cardinality rules;
- deterministic connection identity;
- immutable workflow replay/conflict semantics;
- layout remains non-authoritative.

Do not add dynamic graph mutation, scheduler semantics, wait/resume, loop or task fan-out.

### G. Compiler Generalization

Refactor the Product compiler into binding-kind lowering handlers.

Required:

```text
NodeInstance
  -> resolve exact NodeDefinition
  -> select exact binding handler by kind/ref/version
  -> produce deterministic projection plan
  -> validate projection
  -> GraphRepository.publish(...)
```

For this Task only:

```text
MODULE  -> existing Module-backed projection
BUILTIN -> trusted PURE lowering
```

The compiler may switch on the small execution-binding kind contract. It MUST NOT switch on concrete node type names.

A Product node may eventually lower to zero/one/multiple Graph facts; do not preserve a general one-Node/one-Module invariant merely for backward convenience. However, only implement the minimum projection shape actually required by MODULE legacy behavior and the Constant BUILTIN proof.
