## Frozen Semantics To Preserve

### Run

A Run is stable Runtime lineage for exactly one immutable Activation.

Minimum facts:

- `run_ref`
- `activation_ref`
- `execution_ref`
- `current_attempt_seq`
- `fencing_generation`
- `state`
- `terminal_attempt_seq?` only if schema needs nullable future field; do not implement terminal transition
- `terminal_event_ref?` only if schema needs nullable future field; do not implement terminal transition

Exactly one Run belongs to one Activation in v0.1.

### Initial RunAttempt

A RunAttempt identity is:

`(run_ref, attempt_seq)`

For this Task, create only the initial Attempt:

- `attempt_seq = 1`
- state `CREATED`
- one opaque, non-empty fencing token bound to current Run authority
- no `ACTIVE`, `SUCCEEDED`, `FAILED`, `SUPERSEDED`, `CANCELLED`, or `SUSPENDED` transition machinery yet

The implementation-local encoding/generation of the initial fencing token is not frozen architecture. It must be deterministic/replay-safe for the same committed Run identity and must not use wall-clock/arrival-order as semantic truth. Do not create a generic token-provider framework.

### Current-attempt authority

At initial creation, Runtime must atomically establish one canonical current-authority tuple equivalent to:

`(execution_ref, activation_ref, run_ref, current_attempt_seq=1, fencing_generation, fencing_token)`

Run's `current_attempt_seq` and `fencing_generation` are canonical authority facts and must never become partially advanced relative to the current Attempt.

This Task only establishes that tuple. It does not yet perform terminal Commit Fencing.
