## Required Implementation

### A. RuntimeContext live wiring

Make the real `AttemptExecutor.execute()` path construct/pass the bounded `RuntimeContext` required by the trusted host execution seam instead of unconditionally passing `runtime_context=None` when the executing Module legitimately requires host-mediated effects.

Requirements:

1. PURE Modules must retain current behavior and must not gain ambient authority.
2. Effect-capable Modules receive only bounded handles/broker objects derived from already-admitted canonical authority.
3. Module code must never receive `StateStore`, SQLite connection, raw CapabilityGrant/ResourceLease authority objects, Credential values, `ResolvedCredentialHandle`, socket/client/session objects, or unrestricted OS/network objects through RuntimeContext.
4. RuntimeContext construction must be deterministic from canonical execution/admission authority, not caller-supplied privilege claims.
5. Invalid/missing authority must fail closed before an effect is dispatched.

### B. Bounded MODEL_INVOKE Effect class support

Extend the current Effect Authority implementation only as required to support a second bounded effect class representing `MODEL_INVOKE`.

The implementation must preserve the generic frozen EffectOperation lifecycle and must not pretend a real provider call occurred.

At minimum provide a truthful non-consequential/testable dispatch boundary that can exercise:

- EffectOperation durable identity;
- PREPARED before dispatch;
- Attempt/fencing validation;
- CapabilityGrant validation for MODEL_INVOKE;
- optional ResourceLease validation only where the accepted contract requires it;
- class-specific deterministic conflict scope;
- completion/historical outcome recording suitable for the bounded simulated/local path;
- UNKNOWN where outcome evidence is genuinely ambiguous;
- fail-closed invalid/stale authority behavior.

Do not reuse filesystem path/hash evidence as MODEL_INVOKE evidence unless the frozen contract specifically makes that correct. Implement only the minimal class-specific evidence required for the bounded non-real-dispatch path.

### C. Preserve all Effect invariants

Mandatory invariants include:

- PREPARED exists before any dispatch boundary that can become consequential;
- PREPARED does not prove the effect occurred;
- stale Attempt/fencing cannot obtain new dispatch authority;
- dispatch admission linearizes against current Attempt / CapabilityGrant / ResourceLease authority;
- FENCED is not semantic retry clearance;
- active/concurrency conflict clearance and semantic retry clearance remain separate facts;
- historical consequence and active state remain orthogonal;
- EffectOperation and Accounting/Budget state remain distinct owners/lifecycles;
- no Provider/Module/Product code writes canonical EffectOperation state directly;
- each effect class has deterministic machine-checkable conflict scope.
