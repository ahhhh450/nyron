## Frozen / Accepted Rules To Preserve

- requested destination authorization does not imply effective destination authorization;
- selected peer IP must itself satisfy scope/policy;
- every redirect target is a new authorization decision;
- proxy endpoint and ultimate target are independently authorized;
- connection reuse never bypasses current Attempt/fencing/Grant checks;
- credential possession/resolution is never network authority;
- `ResolvedCredentialHandle` object references must never cross into `network/*` APIs (`NYRON-T-20260828-166-F-001` standing invariant);
- `PREPARED` must exist before any future consequential boundary dispatch;
- timeout/disconnect/socket close/cancel request are not proof of no external consequence;
- `FENCED != retry clearance`.

## Required Implementation Scope

### A. Network models

Create under `src/nyron_kernel/host/network/**` immutable models sufficient to represent:

- `RequestedDestination`: canonical scheme/protocol, canonical host, normalized port, operation class, optional path/endpoint restriction reference;
- `EffectiveDestination`: exact selected IP/peer, port, connection/session identity, redirect hop index, optional explicit proxy hop identity;
- `NetworkAdmissionRequest`: exact run/attempt/fencing identity, CapabilityGrant, ResourceLease where applicable, Effect operation/admission reference, requested and effective destination identities.

No model may accept a `ResolvedCredentialHandle`, raw secret, token, header value, socket object, response object, SDK client, or live transport handle.

### B. Pure destination classification

Implement pure, deterministic, I/O-free helpers using caller-supplied strings/data only:

- host canonicalization including IDNA and label-boundary-safe matching;
- scheme/port normalization;
- IPv4/IPv6 parsing and canonicalization;
- IPv4-mapped-IPv6 normalization before policy classification;
- loopback/private/link-local/unspecified/multicast/reserved/special-use classification;
- fail-closed invalid/ambiguous input handling;
- explicit host/IP/port/scheme scope matching;
- redirect target represented as a fresh requested-destination identity;
- explicit proxy identity only; no ambient/system/env proxy concept.

Do not perform DNS resolution.

### C. NETWORK_ACCESS scope data

Use the existing Capability registry mechanism to define/register only the minimum `NETWORK_ACCESS` scope shape needed by this bounded foundation. This is new scope data, not a new authority model.

The scope must be capable of independently constraining at least:

- scheme/protocol;
- canonical host/host pattern;
- port;
- selected effective IP/range policy;
- explicit proxy allowance/identity where represented.

Do not redesign CapabilityAuthority.

### D. Admission-only boundary seam

Implement `NetworkAdmissionBroker.admit_simulated_dispatch(...)` or equivalent that:

- performs no socket/DNS/TLS/HTTP/SDK I/O;
- independently re-reads the current exact Attempt/fencing state;
- independently verifies the exact CapabilityGrant is active and bound to the same run/attempt;
- independently verifies ResourceLease if the request declares one;
- independently verifies Effect is still `PREPARED` and correctly bound for this admission;
- validates requested destination and exact selected effective destination against the `NETWORK_ACCESS` scope;
- rejects redirect/proxy/reuse identities that have not independently passed the same required checks;
- returns only a non-consequential admission value/evidence object suitable for tests.

No cached/advisory Capability result may be promoted into authority.

### E. Credential orthogonality

Network code must not import, store, accept, expose, or forward `ResolvedCredentialHandle`.

The Network foundation may reference only non-secret credential binding identity if absolutely necessary for an identity check; preferably it should remain completely credential-value-agnostic.

A valid/revoked credential must never change destination authorization outcome.

### F. No historical-outcome invention

Do not add a real Network Effect class, Recovery behavior, timeout/cancel historical outcome, retry engine, or transport evidence semantics in this Task.

Admission failure/success must not itself claim external dispatch occurred or did not occur.
