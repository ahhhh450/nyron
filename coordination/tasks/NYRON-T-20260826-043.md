### Q3 — Real authority-consumption linearization (release-blocking)

This is the central review point.

Prove the exact dispatch admission establishes a real serializable/linearizable order for one `operation_ref` against all of:

- current Runtime Attempt / fencing;
- exact CapabilityGrant identity, ACTIVE/time validity, Attempt binding, machine-checkable effect scope;
- exact Resource identity/state;
- exact ResourceLease identity, ACTIVE/time validity, Attempt/Resource binding.

Explicitly analyze SQLite transaction/locking semantics and all connection-scoped helpers.

`validate -> commit/return -> later external use`

without durable exact-operation admission ordering is a `BLOCKING` correctness/security finding.
