## Purpose

Close the blocking Runtime admission correctness gap introduced/exposed by multi-instance `GraphRevision` support.

Task 172 proved that frozen Runtime Orchestration admission requires all ModuleInstanceRevision / ModuleDefinition / config references in the Graph revision to resolve before canonical WorkflowExecution admission is created, while the current `ExecutionAdmissionGate.admit()` checks only the first instance through the backward-compatibility `graph.module_instance_revision` property.

This Fix must make admission validate every instance in a multi-instance Graph before admission succeeds.
