### A. StateStore

Provide the minimal transactional SQLite-backed StateStore required by this Segment.

Requirements:
- Python 3.11+ / stdlib `sqlite3` is an implementation choice from the accepted plan, not frozen architecture.
- explicit transaction boundaries;
- durable schema needed for ModuleDefinition, GraphRevision, ModuleInstanceRevision and reference resolution;
- no speculative repository/provider/ORM abstraction;
- Module code must never receive raw store access.

### B. ModuleDefinition Registry

Implement immutable register/resolve behavior for `ModuleDefinition@version`.

At minimum satisfy the accepted plan / frozen invariants for:
- immutable version identity;
- exact resolution to one registered definition;
- duplicate same ref/version with conflicting contract rejected;
- input/output/config schema validation;
- effect/capability declaration validation required by the frozen Module registration contract, even though this slice will seed only PURE/no-capability modules;
- deterministic rejection codes where frozen/accepted plan defines them.

Do not implement CapabilityGrant, Resource, EffectOperation, plugins/providers, or generalized extension frameworks.

### C. GraphRevision / ModuleInstanceRevision

Implement immutable publish/resolve behavior sufficient for one-module graphs.

Requirements:
- immutable GraphRevision identity;
- immutable ModuleInstanceRevision pinned to an exact `module_ref@version`;
- unresolved module reference is fail-closed / non-executable;
- preserve `static_accounting_scope_ref` as a pinned graph/module-instance fact for later authoritative Accounting admission validation;
- do not locally own or validate Accounting truth in this Task;
- do not implement WorkflowExecution admission yet.
