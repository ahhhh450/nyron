Preserve these D-009 separations exactly:

```text
external input != HumanResponse
HumanResponse != Runtime resume
HumanDecisionEvidence != CapabilityGrant
approval evidence != authority bypass
transport arrival order != authority
```

Human Interaction owns only its canonical request/accepted-response/binding/aggregation/evidence truth. It must not become owner of identity truth, Project/Workspace role truth, CapabilityGrant, Runtime Attempt/Subscription/EventDelivery/resume truth, RecoveryDisposition, EffectOperation, notification delivery truth, UI truth, Distribution truth, or PWP canonical state.

Invalid, unauthenticated, unauthorized, schema-invalid, stale, unbound or terminal-state input must not become canonical `HumanResponse` truth.

Response acceptance versus satisfy/expire/cancel/supersede races must resolve through one Human-Interaction-owned local transactional serialization boundary. Transport arrival order is not authority.

Same stable response identity plus the same semantic payload/evidence binding may be idempotent. Reuse of the same stable response identity with different semantic content or binding must fail closed and leave prior canonical truth unchanged.

Late response after terminalization must not alter canonical terminal truth in this slice.

If correctness would require inventing an unfrozen cross-owner Runtime, ingress, selector, role, identity, Capability or other Owner contract, stop and report `ESCALATION_REQUIRED` in the Result/checkpoint. Do not improvise architecture.
