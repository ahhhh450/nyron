## 3. Required Semantics

Implement the smallest correct Accounting-owned settlement slice covering:

### A. Known actual settlement

For a `RESERVED` BudgetReservation with accepted canonical actual usage facts:

- actual `<` reserved: commit the known actual exposure and release the known unused remainder;
- actual `==` reserved: commit exactly the actual exposure;
- actual `>` reserved: record the full actual exposure, never truncate to the reserved estimate, and record the overrun / settlement delta.

Actual usage truth comes from canonical UsageFact / UsageAdjustmentFact state. Estimate is not actual truth.

### B. Exposure conversion

Settlement must atomically and consistently convert owner-local reservation exposure into committed/released exposure across the complete applicable accounting ancestry.

No state may claim capacity was released while the reservation/canonical counters still retain the same active reserve, or vice versa.

### C. Overrun

When actual exceeds reserved:

- preserve the full actual usage;
- record the overrun delta;
- apply committed exposure to all applicable governing scopes;
- future hard-limit reservations must observe the resulting reduced/negative headroom;
- do not retroactively invalidate already-incurred EffectOperation or usage truth.

### D. Adjustment / refund

Usage correction must remain append-only through Track-A UsageAdjustmentFact / compensating fact semantics.

Do not rewrite historical UsageFact rows to make exposure match a later correction.

Settlement must recompute/apply canonical exposure from accepted immutable facts in a replay-safe manner without double applying a prior adjustment.

### E. Idempotency / replay

The same settlement request / exact canonical fact set replayed after commit must not double-commit usage, double-release reserve, or double-apply overrun/adjustment.

Stable identity conflicts must fail closed.
