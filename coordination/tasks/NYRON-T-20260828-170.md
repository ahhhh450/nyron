## Product Direction — Binding Requirement

Nyron's user-facing node model is a **module assembly node system**, not a visualization of every Runtime/canonical object.

Target layering:

```text
Module
  ↓
ProductNodeDefinition
  ↓
NodeInstance + Ports + Connections
  ↓
VisualWorkflowRevision
  ↓ compile/project
Runtime GraphRevision
  ↓
Execution Runtime
```

The Product layer may package several lower-level canonical mechanisms behind one user-facing node.

Examples:

```text
LLM Node
→ Provider + Credential + Network + Accounting + Effect

Human Approval Node
→ HumanRequest + HumanResponse + HumanDecisionEvidence + Runtime suspension/resume

Filesystem Node
→ Workspace boundary + Capability + Resource/Lease
```

Do **not** default to exposing `HumanRequest`, `HumanResponse`, `EffectOperation`, `CapabilityGrant`, `Packet`, `Delivery`, `Activation`, `Run`, `Attempt`, or similar canonical objects as separate Product Nodes merely because they exist in the Runtime model.

The target product experience is closer to ComfyUI / Langflow / Flowise-style modular composition, while preserving Nyron's existing canonical authority boundaries behind the Product layer.
